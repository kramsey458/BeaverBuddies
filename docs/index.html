Playing together takes three steps

No router settings, no virtual networks. If you both have Timberborn on Steam, you are a few clicks away.

  1. Everyone installs the mod

    Same download, same version, then restart the game. Install guide

  2. The host invites a friend

    Load a save, choose Host co-op game, then Invite Friends and pick your friend in Steam's overlay.

  3. Your friend joins, you start

    When your friend appears in the player list, the host chooses Start Game. Everyone builds in the same colony.

What you get

Everything the original BeaverBuddies does, plus the parts that make a long co-op session actually work.

Steam friend invites

Invite a friend from Steam's own overlay. Connections go straight between you when Steam finds a route and are relayed through Steam otherwise, so there is no Hamachi and no port forwarding. Direct IP still works too.

A connection panel

See who is connected, each player's ping, whether you are in sync, and the tick rate at a glance. Collapse it to one line or hide it completely.

See your teammates

Colored, translucent cursors with names, selection outlines, and Viewing / Editing labels on buildings. Restyle each player's cursor in the Player cursors dialog.

Fewer crashes and desyncs

Fixes for the water, animation, random-number, saving, demolition and input problems that knocked sessions out of sync or crashed them.

Problems are explained

Joining with a different build is refused before the save is sent. Failed connections and multiplayer actions end with a plain-language reason instead of a silent hang.

Quicker and lighter

A guest's actions reach the host about half a tick sooner (roughly 0.3 seconds at normal speed), and the mod does less work every tick and every frame.

Steam invites

Skip the port forwarding

Choose Invite Friends and your friend gets a normal Steam invitation. If their game is closed, Steam launches it and joins for them.

Confirmed  Working in real playtests between the maintainer and a friend.

  • Friends only. The host opens a friends-only lobby and only accepts players who joined it. A stranger who knows your Steam ID cannot connect.
  • Your address stays private. Valve documents that relayed connections keep players' IP addresses hidden from each other.
  • Direct IP still works. Both options are offered when you host, so Hamachi and port forwarding keep working. Steam problems can never stop you hosting over direct IP.
  • Clear errors. If a connection fails, you get Steam's own reason in plain language and in the log.
  • The current API. The original used Valve's older networking API, which Valve marks as deprecated. This fork uses the one Valve recommends.

Both players need to be online in Steam and to own Timberborn on Steam.

Connection panel

Know how your session is doing

A small panel in a corner of your screen during multiplayer games. It only reads: it sends no gameplay events, and if it ever fails it switches itself off.

StatusWhat it means
In syncNormal. Everything is running together.
Catching upGuests only: your game is a few ticks behind the host.
Waiting for hostGuests only: nothing has arrived from the host for a moment.
Connection unstableSomeone has stopped responding for five seconds.
Out of syncA desync was detected.
DisconnectedThe session has ended.
  • Ping is the round trip to the host. Green is 80 ms or less, yellow up to 160 ms, red anything higher or no response.
  • Tick rate and speed show how fast the simulation is really running, and guests see how many ticks they are behind the host (0 or 1 is normal).
  • Connection shows whether players are connected directly or through Steam.
  • Click the title to collapse it to a single line. Your choice is remembered.
  • Hide it or move it to any corner in Mod Settings, or bind the optional Toggle connection panel key.

Ping is measured by the mod's network layer, so it means the same thing over Steam, Hamachi and direct IP.

Player activity

See what your teammates are doing

Other players' cursors, selections and building edits show up on your screen, so you stop building on top of each other.

  • Cursors are colored and translucent, with a name label. They are shared in world space, so cameras can be anywhere.
  • Selection outlines use the game's own outline in that player's color.
  • Viewing / Editing labels appear on buildings. It is an advisory notice, not a lock: both players can still change a building.

Make each cursor your own

Open Options (Esc) and choose Player cursors. Each connected player gets a card:

ControlRangeDefault
ColorTheir color, 10 presets, or exact RGBTheir color

These are display-only choices that stay on your machine. They are never sent to other players, are remembered by player name, and cannot affect the simulation.

Under the hood

Stability work, and how sure we are of it

Each fix is marked by how well it is confirmed. Confirmed means it was verified in a real multiplayer playtest; Tested means automated regression checks cover it but it has not been confirmed in a live session.

Water no longer depends on frame rate Confirmed

Players at different frame rates used to see different water, which caused desyncs. The water now follows the simulation's own clock. It resolved a reported "badtide" desync.

Animation crash fixed Confirmed

A path cursor that could move backward between ticks, and non-finite visual coordinates, no longer crash the game.

Builds are checked before the save is sent Tested

The original only warned about a version mismatch after the save had loaded. The fork compares the game version and the exact mod build first, with a time limit and a clear message.

A failed action stops safely Tested

If a multiplayer action fails, replay stops, the session pauses and peers are told, instead of two games quietly drifting apart.

More deterministic random numbers, saving and ordering Tested

Nested random-number scopes are restored even after errors, a stale saving flag is cleared, and water sources are applied in a consistent order.

Demolition and input fixes Tested

A replayed demolition selection that included already-demolished buildings no longer ends the session, equal-distance demolition jobs are chosen deterministically, and input state is recovered after a desync.

The full list is in the changelog.

How it works, in one minute

Timberborn is a single-player game, so BeaverBuddies keeps every player's copy of the game identical instead of streaming one game to everyone.

  1. Everyone starts from the same save. The host sends the save when a friend joins.
  2. Every action is mirrored. Building, changing a recipe or setting a priority is sent to the host, which decides which tick it happens on and sends it to everyone.
  3. The game is deterministic. Given the same save and the same actions on the same ticks, every copy of the game plays out exactly the same.

That is why everyone must run the same build, why other mods should match, and why nobody can join once the host has started. When something breaks that sameness, that is a desync. The original project's wiki explains the design in more detail.

Good to know before you play

  • Everyone must run the exact same build of the mod and the same version of the game.
  • Other mods and settings are not compared. Keep your mods and simulation-affecting settings identical.
  • Join before the host starts. Nobody can join after Start Game.
  • Desyncs can still happen. This fork removes known causes; it cannot promise none. Keep backups of your saves.
  • Tested with two players on Windows and Steam. Larger groups and other platforms have not been tried.

More answers are in the FAQ, and Troubleshooting covers what to do when something goes wrong.

What's new in 1.0.2

  • Guests keep up at high speed. At speed 7 a guest used to sit 3 to 5 ticks behind the host and never recover, because catching up only started once it was more than 7 ticks behind. It now starts at more than 2 ticks behind, at any speed, so a guest sees the result of its own actions sooner.
  • No extra cost. The catch-up speed changes far less often than before, and the host, a paused game and the 10x cap are unchanged.
  • It only changes how fast a guest works through ticks it already has, so it cannot change what anyone simulates.

Every player should install 1.0.2: the game warns when mod versions differ. Read the full release notes.
