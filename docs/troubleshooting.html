Troubleshooting

Find your symptom, try the fixes in order, and if it is still broken, collect the logs and ask for help.

Check these first

Most multiplayer problems come from a mismatch between the players. Before anything else, check that everyone has:

  • the exact same download of the mod (the mod list shows the version, and it must be the same zip, not just the same number),
  • the same version of Timberborn,
  • the same other mods enabled, at the same versions,
  • and has fully restarted the game since installing or updating.

Installing and loading

The mod does not load, or does not show in the mod list

Try this

  1. Check the folder. You should have Documents\Timberborn\Mods\BeaverBuddies-Stability-Fork\version-1.1\manifest.json. A common mistake is an extra nested folder after extracting the zip.
  2. Make sure Harmony and Mod Settings are installed and enabled. The mod needs both.
  3. Enable BeaverBuddies - Stability Fork in the mod manager and restart the game.
  4. The mod is built for Timberborn 1.1 (tested on 1.1.2.4). Older game versions will not run it.
  5. Open %USERPROFILE%\AppData\LocalLow\Mechanistry\Timberborn\Player.log and search for BeaverBuddies v1.0.2 is loaded!. If it is there, the mod loaded and the problem is elsewhere.
There are two BeaverBuddies in the mod list, or things behave strangely

Why

This mod and the Workshop BeaverBuddies share the same mod ID, and so does any second copy in your Mods folder, including an old BeaverBuddies-StabilityPreview folder left over from an earlier download. They conflict.

Try this

Keep exactly one BeaverBuddies. Unsubscribe from the Workshop version, delete any extra copy (and the old BeaverBuddies-StabilityPreview folder) from Documents\Timberborn\Mods, then restart the game.

Joining a game

Joining is refused with a version or build message

Why

When someone joins, the mod compares the game version, the mod version and the mod's own files, before the save is sent. It refuses any difference, because two different builds cannot stay in sync. A copy someone compiled themselves can be refused even when the version number matches, and an old version still running in memory is detected too.

Try this

  1. Have everyone download the same zip from the latest release.
  2. Replace the BeaverBuddies-Stability-Fork folder, then fully restart Timberborn on every computer.
  3. Check that the game versions match.
Invite Friends does nothing, or my friend gets no invite

Try this

  1. Right after hosting starts, the Steam lobby is still being created. Wait a moment and click Invite Friends again. The Steam overlay should open.
  2. On the host, make sure Enable Steam Networking is on in Mod Settings (it is by default).
  3. Both players need to be online in Steam. The friend must be on your Steam friends list and own Timberborn on Steam.
  4. Both of you need the same build of the mod and the same game version.
  5. If Steam still will not connect, host with a direct IP or Hamachi instead. Steam problems never stop direct IP hosting.
The invite says the host has already started

Why

Nobody can join once the host chooses Start Game. An old invite now explains that instead of hanging.

Try this

The host saves and hosts again, then sends a fresh invite. Have your friend join before the host starts.

Joining over Steam takes forever or fails with a Steam message

Why

Steam connects players directly when it can find a route and relays through its own network otherwise. Failures end with an explanation that includes Steam's own reason, for example "The connection timed out. Steam could not find a working route between you." The same detail is written to Player.log.

Try this

  1. Read the message. It says what Steam reported.
  2. Make sure you are both on the exact same build. If joining sits on a loading message and never finishes, that is the first thing to rule out.
  3. Try again. If it repeats, use direct IP or Hamachi.
  4. If it keeps failing, collect both players' logs and ask for help.
Direct IP will not connect

Try this

  1. The host must already be hosting and must not have chosen Start Game.
  2. Use the right address: your public IP for the internet, or the virtual-network address (for example from Hamachi) if you use one.
  3. The default port is 25565. Your router must forward it to the host's computer, and your firewall must allow Timberborn.
  4. Port forwarding is the hard part. A virtual LAN such as Hamachi avoids it and has been tested. So does a Steam invite.

While playing

The connection panel shows something other than "In sync"
StatusWhat it means and what to do
Catching upGuests only. Your game is three or more ticks behind the host. Brief spells are normal. If it keeps growing, your connection or computer cannot keep up, so check your ping and try a lower game speed.
Waiting for hostGuests only. Your game has used everything the host sent and is waiting for more. A flash is normal. If it stays, check the connection.
Connection unstableSomeone has stopped responding for five seconds. Check their connection. If it does not recover, the session may end.
Out of syncA desync was detected. See the next item.
DisconnectedThe session has ended. Rejoin, or have the host rehost.

Ping colors: green is 80 ms or less, yellow up to 160 ms, red anything higher or no response.

A desync: "A connected player desynced and cannot continue playing"

Why

The players' games have drifted apart. Every copy of the game must make exactly the same decisions, and something made one of them differ. This fork removes many known causes, but it cannot promise none.

Try this

  1. The host chooses Save and Rehost.
  2. Steam guests accept a fresh invite; direct IP guests reconnect.
  3. You may need to restart the game if problems persist.

Things that cause it

  • Different mods, or different mod versions. The mod only compares itself, not your other mods. This is a classic cause.
  • Different settings that affect the simulation, for example Reduce the number of forced pauses. Keep them identical.

Keep backups of your saves. If it keeps happening, collect both players' logs.

"Multiplayer has stopped because this action may have changed only part of the game state"

Why

A multiplayer action could not be completed on one player's game. Carrying on could leave two games different without anyone noticing, so the mod stops the session.

Try this

  1. Return to the main menu and reload a known-good save before hosting again.
  2. Do not overwrite your good save with the session that stopped.
  3. If it repeats with the same action, collect the logs and say what you were doing.
The game is laggy or my FPS is low in multiplayer

Try this

  1. Turn off Always Use Detailed Logging in Mod Settings, on both computers. It records a lot of extra detail for diagnosing desyncs and noticeably slows the game. It is off by default.
  2. Look at the connection panel. A red ping or a high Behind host value means the connection is the problem, not the game.
  3. Try a lower game speed if a slower computer keeps falling behind.
  4. Make sure both players run the latest release, which does less work every tick and every frame.

Panel, cursors and settings

The connection panel is missing

Try this

  • The panel only appears in multiplayer games.
  • Check Mod Settings, BeaverBuddies, Connection panel. It may be set to Hidden.
  • If you bound the Toggle connection panel key, you may have hidden it with that key.
  • It may be collapsed to a single line (a colored dot, the player count and one ping). Click the line to expand it.
  • It may be in a different corner. See Connection panel position.
I cannot see other players' cursors, labels or pings

Try this

  • Player activity indicators must be on in Mod Settings. A player who turns sharing off disappears from your view until they turn it back on.
  • A cursor is hidden while it is over the game's interface, outside the game window, or off the map. Yours is hidden while the game window is not focused.
  • Open Options, Player cursors and check that you have not made that player's cursor tiny (size 50% is the minimum) or nearly invisible (transparency goes up to 90%). Reset restores the defaults.
  • For pings, bind a key for Ping Location in the game's keybinding settings.

Collecting logs

If you ask for help, logs from both players are what make a problem diagnosable. Steam failures and desyncs record their details there.

  1. Close the game so the log is complete.
  2. Open %USERPROFILE%\AppData\LocalLow\Mechanistry\Timberborn in Explorer (paste it into the address bar).
  3. Copy Player.log. If the problem happened in an earlier session, also copy Player-prev.log, the log of the session before.
  4. If a desync happened with detailed logging on, the water diagnostics are saved in the BeaverBuddiesDiagnostics folder next to the logs. They are written only on your computer and are never uploaded.
Before you share

Logs contain file paths, which include your Windows user name. Look through the file before you post it if that matters to you.

The Post Bug Report button in the desync dialog does not upload anything in this fork's builds, because they contain no upload token. Send the files by hand instead.

Leave Always Use Detailed Logging off unless you are asked to turn it on. It costs performance.

Getting help

Open an issue on the project's GitHub page and include:

  • what you were doing and what you expected,
  • the mod version, the game version, and whether you connected over Steam or direct IP,
  • both players' Player.log files.

Also check the FAQ, which answers the common questions.
